# MapControl desktop

## Dev-режим

Без заполненного `bundle/version.txt` обёртка ищет `../src/server.js` и запускает его системным Node.js. Запускать из `desktop/` или собирать из дерева исходников можно как раньше.

## Сборка одного файла

Из корня проекта:

- `node scripts/make-dist.cjs` — обычный `desktop/MapControl.exe`: оператор вписывает ключи после первого запуска.
- `node scripts/make-dist.cjs --with-keys` — `desktop/MapControl.exe` под ключ: на чистой установке настройки сразу готовы к работе.
- Обычный exe подходит для проверки и любого клиента, которому нужна отдельная настройка.
- Exe под ключ отдавать только доверенному заказчику: ключи извлекаются из файла и оплачиваются по его использованию.
- Значения берутся из живого `.env` только на время локальной сборки, в Git не попадают.

Иконка встраивается существующим `rsrc_windows_amd64.syso`. Если его нет, сначала:

```
go install github.com/akavel/rsrc@latest
cd desktop
rsrc -ico icon.ico -o rsrc_windows_amd64.syso
```

`desktop/bundle/` — только staging: в Git сохраняется `.gitkeep`, остальное готовит `make-dist.cjs`.

## Runtime и данные

Вшитые Node.js, `src/`, `public/`, конфиг и зависимости распаковываются в `%TEMP%\MapControl\<версия>`. Повторная распаковка той же версии не выполняется.

Настройки и пользовательские данные находятся в `%APPDATA%\MapControl\`:

- `.env` — создаётся из вшитого `.env.example`, существующий файл не перезаписывается;
- `ПРОЧТИ.txt` — инструкция оператору;
- `data\submissions\` — черновики, отправленные заявки и фотографии.

Для изолированной проверки можно задать `MC_USER_DIR`; рабочий exe этот параметр тоже учитывает. Обычная сборка не содержит секретов; `--with-keys` встраивает только заданный whitelist из живого `.env` и предназначена для доверенного заказчика.
