# Задача 0013 — выкатка приёмника в прод + проверка связи

- Проект: Zavodsvay-Static (задание трекается здесь, в MapControl) · Статус: ЗАМОРОЖЕНА (прод не трогаем, решение пользователя 2026-09-25) · Дата: 2026-09-24

## Цель

Очередь заявок живёт на проде: `pages/inbox/` залит по FTP, закрытый `inbox-config.php` создан вне webroot, прод-эндпоинт отвечает и узнаёт токен. Писем и публикаций в этой задаче нет — только транспорт.

## Входит

- По FTP (креды — только `tools/.env` в Zavodsvay-Static, в git и в отчёт не тащить): залить `pages/inbox/` в `/www/zavodsvay/` поверх (сверить дерево после заливки листингом), создать `<home>/inbox-config.php` (`['token' => сгенерированный длинный случайный, 'notify_to' => 'stas@zavodsvay.ru']`, формат как `callback-smtp-config.php`).
- Значение токена в отчёт НЕ писать (файл задачи коммитится). Сгенерированный токен положить в Temp-файл (`C:\Users\alexa\AppData\Local\Temp\opencode\inbox-token.txt`, только значение, без пояснений) и указать в отчёте путь — штаб сам разложит его в живой `.env` MapControl.
- Проверки с продом (только чтение и отказы, без приёма заявок): `GET /inbox/` без токена → 401; `GET /inbox/?token=...` → 200 со списком (пустым); `POST` без токена → 401/403. POST с валидным пакетом НЕ слать (это 0014).

## Не входит

- Тестовая заявка в прод-очередь, approve/reject, add-object, деплой карты (это 0014 и работа оператора). Код приёмника не менять; если прод ругается на код — стоп и к штабу, не чинить на проде.

## Старт (указатели)

- Приёмник: `pages/inbox/index.php` (шапка — контракт), `data/inbox/.htaccess`, `data/inbox/.gitignore`.
- Образец закрытого конфига и FTP-укладка: `pages/callback/index.php` (шапка), `tools/.env`, `tools/deploy.js` (читать, не запускать вслепую).
- Контекст статики: `docs/CONTEXT.md` (история звонка и почты — там же грабли хостинга).

## Приёмка

- Листинг прод-каталога показывает `pages/inbox/index.php` со свежей датой; `inbox-config.php` лежит вне webroot (проверка листингом home, значение не читать в отчёт).
- Три проверки выше — с кодами из живого прод-домена (https), выводы в отчёт.
- Temp-файл с токеном существует, в git не попал (`git status --short` в обоих репо — без него).
- `git status --short` Zavodsvay-Static: без изменений кода (только если правился контекст — отдельно и явно).
- Коммит не нужен (кода нет); пуш не нужен. Отчёт в этот файл, статус «на проверке».

## Ограничения

- `data/map.json`, `pages/objects/`, `sitemap.xml`, `assets/`, `old/`, любые `.env` и закрытые конфиги — не коммитить, значения в отчёт не писать.
- Прод-очередь не засорять: ни одной тестовой заявки в этой задаче.
- Стоп и спроси штаба: код на проде ведёт себя иначе чем на стенде; FTP-дерево не совпадает с ожидаемым; хостинг режет что-то новое.
