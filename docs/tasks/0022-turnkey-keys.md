# Задача 0022 — сборка «под ключ» (ключи вшиты)

- Проект: MapControl · Статус: в работе · Дата: 2026-09-25

## Цель

Заказчик запускает exe и работает сразу, без вписывания ключей: сборка отдельной командой кладёт боевые значения из живого `.env` в bundle, первый запуск создаёт готовый `.env` в пользовательском каталоге.

## Входит

- `scripts/make-dist.cjs`: флаг `--with-keys` (без него — как сейчас, пример). При флаге читает живой `.env` из корня и переносит whitelist (`YANDEX_MAPS_API_KEY`, `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, `SMTP_HOST/PORT/SECURE/USER/PASS`, `MAIL_FROM/MAIL_TO`, `INBOX_TOKEN`) в `bundle/app/.env` (поверх примера). Версия сборки помечается `-keys` (видно в `version.txt`).
- Проверка флага: сборка без ключей не подхватывает ничего лишнего (diff bundle без `.env` — только пример).
- Документация сборки (`desktop/README.md`, 5 строк): когда какую команду гнать, кому какой exe отдавать.

## Не входит

- Ротация и отзыв ключей, раздельные ключи на заказчика (это решение пользователя, не код). Сервер и фронт не менять.

## Старт (указатели)

- Сборщик: `scripts/make-dist.cjs`; пользовательский каталог: `prepareUserDir` в `desktop/main.go` (копирует `.env` только если нет — уже так).

## Приёмка

- `node --check scripts/make-dist.cjs`.
- Сборка с флагом в тестовый `MC_USER_DIR` → созданный `.env` содержит боевые значения (сверить длину/маску, не светить целиком); сборка без флага → только пример.
- Тестовый запуск с флагом: `/api/config` отвечает, ключ карт настоящий (скрипт Яндекс 200).
- Мусор (тестовый user dir, черновики) убрать. Живой `.env` никуда не копировать кроме bundle-staging (gitignored).
- `git status --short`: только `scripts/make-dist.cjs`, `desktop/README.md` (+ этот файл). Bundle, exe, `.env` в коммит не идут.
- Коммит `№0022: сборка под ключ` + пуш в `main`.

## Ограничения

- Значения ключей в отчёт и в git — никогда (только длины/маски). Обычная сборка по умолчанию БЕЗ ключей.
- Стоп и спроси штаба: если whitelist надо расширить/срезать.

## Порядок работы

Прочитай контекст проекта → сделай → проверь по приёмке → допиши отчёт ниже → статус «на проверке», жди.

## Решение штаба (2026-09-25, блокер снят без заполнения токена)

`INBOX_TOKEN` в живом `.env` пуст — и это нормально: `inbox.enabled=false`, приёмник заморожен, токен нигде не используется. Строгий fail-fast на 12/12 здесь over-strict.

Допилить: `INBOX_TOKEN` обязателен только при `inbox.enabled=true` в `config/site.json` (читать флаг в `main()`); при `false` — warn в консоль, не fail. Остальные 11 — строго как сейчас. После этого довести `--with-keys` до зелёного, сдать (статус «на проверке», коммит/пуш — по регламенту сессии).
